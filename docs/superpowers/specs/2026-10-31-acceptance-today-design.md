# Acceptance evidence and today's owner actions
Approved bounded approach: extend task center rather than replace TaskResult or native approvals. Two connected features, no new permissions/services/costs.

Approaches: (1) fake checklists are rejected because user actions are not provider evidence; (2) new privileged GitHub/Vercel integration is outside scope; (3) selected: public GitHub read-only commit/status evidence, explicit unavailable deployment/functional capability, manual acceptance separately attributed, and a fully functional native-source owner-action queue.

Acceptance records retain exact expected SHA, known project, criteria, due date, immutable evidence observations and explicit manual pass/fail report. No automatic completion from HTTP200, commit presence, CI success or a checkbox. Fixed GitHub API host, validated repository slug and full40hex SHA; no arbitrary fetch URL, redirects or returned URLs followed. Allowlisted project catalog initially NOIRXU AI, OFFSCRIPT and Film Lab. Public commit and status reads only, bounded response/time; rate-limit cache is durable per owner with CAS lease. User manually requests checks; loading a page never contacts providers. Vercel direct capability absent: deployment stage explicitly unverified, CI metadata is not production READY. Runtime URL is an expected project URL, never automatically opened/fetched. Functional result remains manual with criteria, observations and timestamp; never silently changes goals/task execution.

Today owner-action view derives from existing tasks, active/finished goals and acceptance records. One row per source ID, sorted by priority/due date; distinct action-needed, waiting and resolved groups. It routes native approval back to its task card, connections back to settings, and goals/acceptance to actual editors. No mark-done checkbox, new push or scheduler. Source changes resolve rows; failed source reads show an error, not an empty success. Deadline is Taiwan calendar today. No unrelated disconnected integration nags.

Security: same-origin authenticated writes, owner-scoped encrypted existing AgendaStore CAS, bounded inputs, no raw provider payload retention or secrets, no model tool acceptance without human report. Reports cannot establish provider facts. Cancelled records and concurrent checks use revision guards; stale results cannot overwrite new intent. Manual report may resolve only the acceptance review item, never a tool's native approval.
