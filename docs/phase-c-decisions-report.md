## 3. 已修復的風險與尚待處理的問題

### 已修復

1. **飲水同時寫入會互相覆蓋**：改用 compare-and-set 加重試，已在真實資料庫驗證。
2. **錯誤訊息變成「內部錯誤」**：伺服器共用物件有時建在另一個路由的程式包裡，錯誤類型判斷會失效，使用者只看到「內部錯誤」。改用全域標記辨識，有測試。（這是端對端測試時發現的。）
3. **對話載入完成前送出訊息會被覆蓋**：伺服器模式下，載入完成前不能送出。
4. **打開對話就會改動版本號**：會讓另一台裝置下一次存檔誤判衝突，已修正。
5. **一個依賴系統時鐘的測試**：日期改變後會失敗，已固定時間。

### 尚待處理

1. **Preview 環境沒有設定**，無法實機測試（見最後一節）。
2. **SSL 驗證**：正式站連資料庫時沒有驗證憑證（`rejectUnauthorized:false`，Phase 1 就記錄過的風險）。要先在 Preview 確認 Supabase 憑證設定後再改。
3. **登入失敗鎖定**只對單一伺服器實例有效。
4. **GitHub 排程不穩定**（Phase 1 觀察到）：目前的提醒推播仍依賴它。
5. 有一次全部測試出現 1 項無法重現的失敗；之後全部測試又跑了 20 次以上、相關的喝水測試 25 次，都沒有再發生，持續觀察中。

## 4. C2 Migration 設計與隔離驗證

### 檔案

| 檔案 | 說明 |
|---|---|
| `supabase/pending/20261023120000_noirxu_ai_history_memory_c2.sql` | Migration（放在 pending，不會被任何自動流程套用） |

| `scripts/test-db.sh` | 一鍵建立隔離測試資料庫 |

### 影響範圍

- 只在 `noirxu_ai` schema **新增** 3 張表：`conversations`、`messages`、`memories`。
- 不修改任何既有資料表、角色、schema 或 extension，不碰 RADAR、Ledger、Journal。
- Loki 目前 166 MB，免費方案上限 500 MB；新表一開始是空的。

### 權限矩陣（`noirxu_ai_app`）

| 資料表 | SELECT | INSERT | UPDATE | DELETE |
|---|---|---|---|---|
| conversations | ✅ | ✅ | ✅（改名、軟刪除、上下文） | ✅（只用於 30 天後清除） |
| messages | ✅ | ✅ | ❌ | ❌（隨對話一起清除） |
| memories | ✅ | ✅ | ✅（編輯、停用、軟刪除） | ✅（只用於 30 天後清除） |

- 列層級安全（RLS）：與現有資料表相同模式。
- 測試已驗證這個角色**不能**：修改或刪除訊息、建立或刪除資料表、讀取 schema 外的資料。

### 索引

- 對話列表：(user_id, updated_at)，只含未刪除的對話
- 匯入去重：(user_id, import_key) 唯一索引
- 清除排程：purge_after
- 訊息順序：(conversation_id, seq) 唯一
- 搜尋：(user_id, created_at)
- 記憶：(user_id, active, updated_at)

### 資料保護

- 每則訊息（含工具結果）都用 AES-256-GCM 加密，金鑰綁定在「對話＋位置」上，複製到別處無法解開。
- 搜尋只看遮罩後的使用者與助理文字（Email、電話、身分證、長串數字都會被遮掉），工具結果不能被搜尋。
- 記憶會拒絕存入：金額、持股、股價行情、密碼、驗證碼、金鑰、卡號、身分證字號。
- 刪除：先標記刪除（所有裝置立刻看不到），30 天後才永久清除；清除時訊息一併移除。

### 多裝置同步

- 兩台裝置同時寫入同一段對話：資料庫會鎖住這一列，先到的寫入成功，後到的收到衝突，重新讀取、合併後再寫入。
- 同步失敗時，未同步的訊息先暫存在那台裝置，下次自動重試。
- 舊版與本機對話上傳一次，之後只有變多時才再上傳；用匯入鍵去重；本機的副本不會刪除。

### 備份與回退

- **備份**：Supabase 免費方案可能沒有可下載的每日備份（需要你在 Supabase 後台確認）。因為這次只新增空表、不修改舊表，執行前我會把 `noirxu_ai` 的完整結構另存，並記錄每張表的筆數。
- **回退**：先在 Vercel 關掉功能開關，再執行 down 檔收回權限，**資料完全保留**，之後可以重新開放。不把刪除整張表當作回退方式。
- 隔離環境已驗證：回退後應用程式角色無法存取、資料筆數不變、舊資料表照常運作；重新授權後恢復正常。

1. 我把 Migration SQL 原文與這份影響評估交給你確認。
2. 你確認後，我在 Loki 執行，並驗證權限與筆數。

## 需要你做的事

### A. 讓 Preview 可以登入（實機驗收 C0、C1 用）

到 Vercel → noirxu-ai → Settings → Environment Variables，下面每一個變數都按右邊「⋯」→ Edit，在 Environments 把 **Preview** 也勾起來，再按 Save：

- `NOIRXU_AI_OWNER_PASSWORD`
- `NOIRXU_AI_SESSION_SECRET`
- `NOIRXU_TOKEN_ENCRYPTION_KEY`
- `NOIRXU_AI_DATABASE_URL`
- `LEDGER_SUPABASE_URL`、`LEDGER_SUPABASE_ANON_KEY`、`LEDGER_APP_URL`
- `JOURNAL_SUPABASE_URL`、`JOURNAL_SUPABASE_ANON_KEY`、`JOURNAL_APP_URL`
- `RADAR_INTEGRATION_URL`、`RADAR_INTEGRATION_TOKEN`
- 有設定的話：`ANTHROPIC_API_KEY`、Google 相關變數

勾完後，到 Deployments 找到 `release/c0-c1` 那一筆，按「⋯」→ Redeploy。

**注意**：這樣設定後，Preview 和正式站會共用同一份 NOIRXU AI 資料（記事、喝水、Ledger 和 Journal 的連線）。Ledger 和 Journal 的寫入一樣要按確認才會執行。

### B. Preview 驗收清單（Mac Safari 和 iPhone Safari 各做一次）

1. 登入，打開 `預覽網址/api/ui?mode=sasuke` 切到新版。
2. 對話：`/早報`、`/分診`（貼一段訊息）、`/喝水 300` 連按兩次，重新整理後數字還在。
3. 側邊欄：新對話、搜尋、重新命名、刪除。
4. 記帳：輸入「午餐 1 元 現金」，出現確認卡片，按「取消」（不寫入）。
5. 到「連線」頁按 RADAR 的「測試連線」。
6. iPhone：點輸入框，鍵盤彈出時輸入框不能被擋住。
7. 打開 `預覽網址/api/ui?mode=classic` 切回原版，原版的對話還在。
